# 音游谱面设计知识库（RPE / Phira 体系）

本文件是 RPEN 内置 AI 谱面助手的设计知识库。内容涵盖：判定线几何、音符类型与判定模型、核心排列手法、噪域机制、缓动数学、采音分层策略、多线架构、密度模型、工程规范、难度定数、玩家认知模型与社区黑话。

**使用方式**：AI 在设计或修改谱面时，通过 `chart_knowledge` 工具按主题检索本文件，再依据检索到的条目做设计判断。检索关键词用中文概念词（术语、机制名），例如「纵连」「噪域」「采音分层」「初见杀」「物量」「快慢刀」「Controls」「缓动」。

## 一、基础逻辑与判定维度

### 1.1 判定线坐标系统

| 维度 | 字段 | 含义 |
| --- | --- | --- |
| X 轴 | `moveXEvents` | 水平位移，正值向右、负值向左。屏幕基准范围约 -675 ~ 675 |
| Y 轴 | `moveYEvents` | 垂直位移，正值向上、负值向下。基准线 0，范围约 -450 ~ 450 |
| 旋转 | `rotateEvents` | 角度。0° 水平，90° 垂直，180° 倒转。正值顺时针 |
| 景深 | 多线图层堆叠 | RPE 无独立 Z 字段，靠判定线层级与 alphaEvents 差异化实现等效遮挡 |

坐标系锚点在屏幕中心。超出基准范围的坐标在数据中合法，是"屏幕外蓄力再甩入"的表演手法的基础。

**Z 序等效做法**：

旋转事件支持贝塞尔曲线自定义（`bezier: 1` + `bezierPoints` 四元组），可设计非标准旋转加速度曲线。

### 1.2 四种音符类型

| 类型 | 编号 | 操作 | 特点 |
| --- | --- | --- | --- |
| Tap 蓝键 | 1 | 接触判定线时点击 | 判定区间最窄，承载主旋律重音 |
| Hold 长条 | 2 | 按住到尾部 | 头部与尾部分离判定，可做长音与滑音 |
| Drag 黄键 | 3 | 触碰/划过即可 | 容错高，用于填充视觉密度、连续音、环境音 |
| Flick 红键 | 4 | 快速滑动 | 无方向限制，用于重音提示与机制切换点 |

**关键机制细节**：

- **Drag 是采音的柔性填充工具**。当旋律采音点过密、使用 Tap 会导致体力消耗不合理时，Drag 可在保持节奏可视化的同时降低操作压力。但过度使用会导致"手感发虚"，玩家难以从打击反馈中获得满足感。
- **Hold 尾部判定陷阱**：判定线剧烈位移或旋转时，Hold 尾部可能出现在与头部完全不同的屏幕位置，必须确保全程路径可追踪，否则出现"手按住了但不知道什么时候松"的挫败感。
- **负流速下的 Hold**：RPE 中流速设为负值时，Hold 尾部出现时整个音符会瞬间完整显示，该行为与本家 Phigros 不符，精确视觉反馈段落应避免。
- **Flick 的平台差异**：触屏设备本质是触摸移动事件检测；PC 端键盘映射下退化为"快速按下再松开"，改变了设计意图。谱面声明中标注平台差异是专业做法。

### 1.3 判定区间与手感模型

| 判定 | 典型窗口 | 含义 |
| --- | --- | --- |
| Perfect (P) | ±80ms | 极窄区间，考验绝对节奏感 |
| Good (G) | ±160ms | 节奏略偏但仍容错 |
| Bad (B) | ±180ms | 判定偏出，打断 Combo |
| Miss (M) | — | 未击打或误差过大 |

**深层逻辑**：

**社区观察**：玩家普遍反馈"判定很松"，某些 24 分交互按 16 分打也能通过。这暗示官方谱面在采音密度上做了策略性取舍——**视觉密度可以高于判定实际的宽容度**，因为玩家倾向跟随主要节奏骨架而非每一个视觉音符。自制谱师可利用这一心理，在密集段使用 Drag 填充视觉密度，而把 Tap 集中在关键采音点上。

## 二、核心手法术语与几何构型

### 2.1 基础排列

| 术语 | 定义 | 物理逻辑 |
| --- | --- | --- |
| 纵连 Jack / Stream | 同一 X 坐标连续排列 | 单手爆发力与耐力；难度取决于数量、间距与落点匹配度 |
| 交替纵连 Trill | X=-200 与 X=+200 快速交替 | 降低单手压力，转为双手协调 |
| 交互 Interaction | 两个以上音符极高频交替 | 对应底鼓军鼓；左右落点绑定音色可自然引导手序 |
| 双押 Chord | 同一时间点两个音符分居左右 | — |
| 多押 Multi-Chord | 三押及以上 | 手机端三押已在可解边缘，需配 Drag/Flick 降低门槛 |
| 阶梯 Staircase | X 轴单向递进 | 强制视线与手部平移 |

**纵连的工程细节**：

**多押的平台边界**：手机端（双拇指）三押已处可解边缘，拇指需快速滑移或借助其他手指。三押以上通常配合 Drag（滑动触碰）或 Flick（快速划过）降低操作门槛。PC 端全键映射完全改变边界，但消耗设备寿命与手指耐力，应在声明中明确推荐设备。

### 2.2 进阶空间拆解

**拆谱 Chord Splitting**：

**轴交互 Axis Interaction**：判定线剧烈旋转或位移时，音符沿新轴向排列。破解关键在于**判定线旋转速度与音符生成时机的关系**：

- 判定线在音符生成**前**已完成旋转并稳定 → 玩家只需适应新轴向（可解）
- 判定线在音符生成**后**才开始旋转 → 玩家可追踪音符本身规避困难
- 判定线在音符飞行途中**持续旋转** → 需动态坐标映射能力（最恶劣）

高难度谱面的轴交互通常配合**短暂视觉预告**（判定线提前 0.5 秒到位并停顿）保证可解性。

**逆向判定 Reverse / 倒打**：判定线翻转 180° 以上，音符从下往上飞。常见应对是**视觉锚点法**——玩家不追踪判定线绝对位置，而是记住"音符从屏幕边缘出现后经过几拍到达判定线"，用时间感替代空间感。设计倒打段时应确保该段 BPM 与音符间距和正打段有足够节奏一致性，让玩家可迁移已有时间感。"转板"在手机端可行但平板端笨拙。

**瀑布 Waterfall**：高密度音符在整个 X 轴平面砸下，视觉压迫感极强。

### 2.3 噪域机制

**噪域 Noise Field**：

**RPE 工程实现**：噪域并非原生功能，而是通过**透明度事件设为负值**来"隐藏判定线及其上所有音符"。噪域本质是判定线级别的可见性控制，而非区域级判定屏蔽。

**风险**：隐藏的音符仍占用物量统计，但玩家看不见也打不到，会在结算时产生困惑。若想实现"区域禁地"效果需多线配合：一条线承载噪域音符并设负透明度隐藏，另一条线承载玩家实际击打的音符。

### 倒打段的 X 镜像几何：180° 翻转会把音符甩出屏幕

判定线旋转 θ 时，音符的屏幕横坐标为 `屏幕X = moveX + positionX × cos(θ)`。判定线翻转 180°（倒打段）时 cos(180°)=-1，符号翻转——原本在左侧（positionX=-428）的音符会落到右侧（moveX - (-428) = moveX + 428），直接冲出 ±675 基准范围。

**实测案例**：谱面 398–416 拍做倒打，L2 判定线 moveX=-467、该线音符 positionX=-428 → 屏幕 X 落在 795~923，完全出界（36 个音符玩家根本看不到、也打不到）；L0 的 -580 → 771~785，出界 4 个。

**正确做法**：

1. 倒打保持窗口内，若正打段音符分布**非左右对称**，把音符 positionX **取反**，用负负得正抵消 cos180°，屏幕落点与正打段完全一致；
2. **若正打段本身左右对称**（如 ±300 双押、±450/0/±450 三押），倒打段**沿用同一组 X 即可**，不必取反——因为对称集合在取反后仍是同一集合。社区成熟谱《Desultory Signals》的 364–404 拍倒打段正是如此：音符 X 值域与正打段同为 -620~620，负值占比 41.0% vs 正打段 39.6%，几乎不变。**判据是"音符集合是否对称"，不是"要不要取反"这个动作**；
3. 翻转过渡窗口（0°→180°→0°）内 cosθ 连续变化，音符会横向漂移 → **过渡窗口内不排任何音符**（实测用 4 拍过渡，够玩家做视觉适应但不放音）；
4. 旋转角与 Y 基准必须绑定推导：`Y = 正打基准 + (倒打基准 - 正打基准) × 角度/180`。否则「180° 保持段」与「180°→0° 过渡段」在窗口边界取值不一致，判定线会瞬移（实测跳变达 445 单位）。

**倒打保持时长**：保持 180° 的窗口应不少于 20 拍，让玩家用时间感迁移正打段的手序；短于 10 拍的翻转只是视觉噪音。

**自检口径**：倒打段必须参与屏外计算（cos180°=-1），用正打口径验算会漏掉整段出界音符。


### 交替流的标准写法：幅度递增的左右交替 Drag

社区成熟谱《Desultory Signals》（AT Lv.18.2）把"交替流"落成了可直接复用的模板：**16 分连续，左右交替 Drag，X 幅度每音递增 20**。

**实测形态**（主线 L0，10.0–12.1 拍）：

```
t=10.000 Drag x=-380      t=10.500 Drag x=-420      t=11.000 Drag x=-460
t=10.125 Drag x=+400      t=10.625 Drag x=+440      t=11.125 Drag x=+480
t=10.250 Drag x=-400      t=10.750 Drag x=-440      t=11.250 Drag x=-480
t=10.375 Drag x=+420      t=10.875 Drag x=+460      t=11.375 Tap  x=-300
                                                     t=11.375 Tap  x=+300
```

**要点**：

1. **幅度递增**是这条手法的灵魂——从 ±380 一路张开到 ±620（X 基准边缘），视觉上是一把越张越开的剪刀，而不是在原地左右点；
2. 交替流用 **Drag 类型**而不是 Tap，因为 Drag 是"弯曲的长条"，左右交替的 Drag 天然形成一条锯齿带，玩家要横向划动而不是点按；这是"用 Drag 表达交替"的正确场景；
3. 交替流要**穿插双押 Tap**（±300）——双押 Tap 负责落点精确、交替流 Drag 负责位移，二者交替出现就是双手分工的观感；
4. 同拍最多 6 音，其中 Tap 双押 ±300 + Drag ±540 同拍共存是常见配置。

**与"假交替流"的区别**：X 在两个值之间来回但不递增 = 玩家原地搓手指；X 递增 = 真的要移动。

**Out / In 语义**：

**工程补充**：

- 缓动类型由 `easingType` 整数字段指定，另支持 `bezier: 1` + `bezierPoints` 自定义曲线。谱师可脱离预设库设计任意加速度曲线，例如"先猛冲然后极缓慢停稳"可用贝塞尔 (0.1, 0.9, 0.2, 1.0) 替代 Expo Out，代价是需反复预览确认视觉节奏与音乐情绪匹配。
- `easingLeft` / `easingRight`（0.0-1.0）是**事件级时间裁剪**，把缓动作用区间限制在 [left, right]，区间外瞬间跳到终点，可实现"缓动到一半突然停止"。
- **速度事件缓动的历史遗留问题**：RPE 早期版本速度事件缓动"不为 1 时，实际速度变化与缓动的导函数形状相同"，1.7.0 版本回归为直接缓动速度数值。同一份谱面在不同版本表现可能不同，使用非线性速度缓动时应在注释中标注版本要求。

### 3.2 特殊演出技巧

**快慢刀 Speed Variation / Rubber Banding**：修改 `speedEvents` 让音符下落视觉速度忽快忽慢，判定时刻不变。**本质是视觉速度与判定时间的解耦**。音符在飞行途中突然加速流速会"瞬间飞到"判定线附近，但判定时刻未提前——玩家若根据视觉位置判断会过早出手。破解快慢刀的唯一方法是**依赖音乐而非视觉**，因此快慢刀应放在鼓点强烈的段落，而非旋律复杂的段落。

**判定线面 JudgeLine Area**：

**多线 Multi-Line**：同时生成 2 条以上判定线分担轨道。

| 分工 | 承担内容 |
| --- | --- |
| 主线 | 高密度 Tap |
| 副线 | Hold、大跨度滑键 |
| 表演线 | 绑定音符做视觉运动，音符本身不参与实际判定 |

**性能代价**：每增一条线就需独立维护 moveX/moveY/rotate/alpha/speed 事件数组。社区曾出现"56 条线"的极端案例，带来文件体积膨胀与编辑认知负荷急剧上升——谱师很难在数十条线的事件表中快速定位要修改的那条。

**专业多线策略（按功能分组）**：判定线 0 为主线（主要 Tap），1-3 为副线（Hold 与大跨度滑键），7-13 为纯表演线。分组好处是调整主线密度时只编辑 0 号线事件，不会误触表演线。

**镜像 Mirror**：左右两条判定线完全对称，强制双手分离。工程实现两条路——手动复制并取反 X（易产生 ±1 数值不一致），或在生成脚本中写镜像函数。追求精度应选脚本化生成。

### 3.3 Controls 音符级表演

RPE 的 Controls 系统在**音符层面**（而非判定线层面）控制 Alpha、Size、PositionX、Skew，参数以关键帧形式作用于音符与判定线的纵向距离。

| Control | 字段 | 对 Hold 的影响 |
| --- | --- | --- |
| Alpha Control | `easing`、`alpha`（0.0-1.0）、`x` | 与 note 自身 alpha 混合计算 |
| Size Control | `easing`、`size`（倍率）、`x` | **不影响** |
| pos Control | `easing`、`pos`（positionX 倍率）、`x` | **不影响** |
| Skew Control | `easing`、`skew`、`x` | **不影响** |

**`x` 字段触发语义**：

**表演应用**：音符在飞向判定线途中逐渐变大（Size Control）、从透明逐渐显现（Alpha Control）、横向漂移（pos Control），与判定线运动叠加可创造"音符从判定线中生长出来"或"音符在飞行中碎裂消散"的视觉叙事。Hold 的视觉表演主要依赖判定线运动，而非音符自身变形。

### 判定线 Y 基准与读谱空间：多线同屏时必须压下半屏

多条判定线同屏时，若所有线的 moveY 都在中心附近摆动，读谱空间会被压掉——玩家上半屏看不到足够长的下落轨迹来预判，左右手分工也被挤在一起。

**实测标尺**：社区成熟谱的主线 moveY 均值约 **-235**（明确压在下半屏），moveX 值域仅 -199~199；对照自造的"绕中心摆"谱（L0 moveY -120~+136），三线全挤在屏幕正中，读者一眼就看出"全挤在中间"。

**做法**：

- 给每条线设一个基准 Y（主线约 -235），线在其上做小幅摆动（±70~±90），而不是让线在 -200~+200 之间游走；
- 倒打时整体升到 +210，音符从屏幕下方向上飞，读谱空间转到下半屏；
- 辅助线横向错开到屏幕两侧（moveX ±310~±550），各自音符的 positionX 朝屏幕中心取，形成明确的左右手分工，而不是三条线平行居中。

**推论**：判定线基准位置是谱面可读性的一级参数，不只是视觉效果。改基准比改音符密度更能改善"读谱空间被压"的 complaints。


### 辅助线的屏外进出：alpha 负值语义与音符可见性对齐

alpha 事件的语义是「上限 255 的整数」：**alpha = 0 只隐藏判定线，音符仍然显示；alpha = -1（负数）同时隐藏判定线及其音符**。做辅助线"从屏幕外进场"必须用负值，否则玩家会看到音符凭空出现在虚无上。

**要点**：

1. 辅助线的可见区间应**恰好等于它参与演奏的段落区间**，其余时段 alpha=-1 完全隐藏，判定线停靠在屏幕下缘（约 -450）而不是画外（如 -800，超出 ±450 基准范围）；
2. 淡入段（-1 → 255 的渐变）**提前约 0.3 拍到位**，保证段落首个音符落在恒定 255 段内；否则音符落在淡入尾巴上会凭空出现；
3. 退场淡出与该段最后一个音符之间留出间隔，不要让最后一个音符踩在淡出段里；
4. 音符排在不可见段不是风格问题，是"打不了"的谱面。

**诊断口径**：对每条线按时刻采样 alpha，若音符的判定时刻落在 alpha < 0 的区间，即为缺陷；落在 alpha = 0 区间时线不可见但音符可见，属另一种表现（会看到没有判定线的音符），同样要避免。


### 正弦呼吸式判定线运动：8 拍 Linear 分段拼正弦

《Desultory Signals》主线的三条轨道（moveX / moveY / rotate）**全部是同周期的正弦摆动**，但实现方式极其朴素：**每 8 拍切一段 Linear 插值，段与段首尾值连续**，一段一段把正弦曲线拼出来。

**实测数据**：

- moveX：每 8 拍一段，取值 `0 → 77.9 → 143.5 → 186.4 → 199.9 → 181.9 → 135.1 → 67.0 → -11.7 → -88.5 → -151.4 → -190.3 → -199.2 → …`，值域 **±199**，完整周期约 144 拍；
- moveY：8 拍一段（少数 6 拍/0 拍），中心 **-300**、振幅 ±45，值域 -430~-246；
- rotate：8 拍一段，**振幅仅 ±14°**（值域 -13.7 ~ +13.9），周期同样约 144 拍。

**这是"呼吸"而不是"翻转"**：±14° 的旋转在 ±675 的屏幕上，音符落点漂移仅 `positionX × (1-cos14°) ≈ positionX × 0.03`，即 ±620 的音符最多漂 20 单位——视觉上是线在轻轻摇，落点坐标基本不变，玩家完全不需要重新定位。

**关键区分**：社区成熟谱确实有"持续缓慢摆动"，但摆幅被严格压在 **±14°** 这种"看不出落点变化"的量级。真正的禁止项是**大角度持续旋转**（如 ±60° 以上全曲慢转），那才会持续改变落点坐标、极不友好。

**做法**：用 Linear 分段拼正弦比直接写 sin 曲线更可控——每段 8 拍、起止值连续，段数少（moveX 66 段 / moveY 85 段 / rotate 76 段覆盖全曲 500 拍），导出体积小，且任意一段都能单独手改。


### 段长阶梯即运动语言：2/4/8 拍各司其职

《Desultory Signals》主线 rotate 共 76 段，**段长分布只有四种**：0 拍（2 段）、2 拍（20 段）、4 拍（19 段）、8 拍（35 段）。段长本身就是一种控制语言：

| 段长 | 用途 | 实测出现场景 |
|---|---|---|
| **0 拍** | 瞬移锚点 | moveY 在第 12 拍处有一段 `-280 → -246.8` 的零长度段，把基准切到正弦曲线上 |
| **2 拍** | 快速微调 | 摆动曲线上的拐点附近 |
| **4 拍** | **急转到位** | 180° 翻转：364→368 拍用 4 拍从 0° 转到 180°，400→404 拍用 4 拍转回 0° |
| **8 拍** | 保持 / 摆动 | 正弦摆动的标准采样步长；180° 保持段（368→400）也用它切成 4 段 |

**规则**：想让玩家"注意到"一个动作，给它一个**明确的短段**（2–4 拍）+ 一个**明确的长保持段**（≥30 拍）；想让线"活着但不打扰"，给它连续的 8 拍等长段。不要用 6 拍、7 拍这类不规则长度去凑过渡——只按设计窗口边界切分。

**easing 的真实用法**：主线 rotate 76 段里 **72 段 easingType=1 (Linear)**，只有 2 段用 6 (Sine InOut)，且这两段正好是 180° 翻转的急转与转回。**结论：Linear 是常态，InOutSine 只用在真正的转折点上**。正弦摆动本身不需要 InOutSine，用 Linear 分段拼接就已经是平滑的。


### alpha 演出节奏：32 拍可见 + 8 拍隐线，尾杀用 4 拍频闪

《Desultory Signals》主线的 alpha 事件共 30 段，构成一套清晰的演出节奏表：

**常态呼吸（每 40 拍一轮）**：32 拍全可见 → 8 拍 `-1 → 255` 淡入（即：线消失 8 拍，再用 8 拍淡回来）：

```
[0.6→32] 255      [32→40] -1→255      [40→72] 255      [72→80] -1→255
[80→112] 255      [112→120] -1→255    [120→152] 255    [152→160] -1→255
[160→176] 255→127（半透明 16 拍）
```

**关键**：隐线段用 **-1**（同时隐藏线与其音符），不是 0。淡入段从 -1 起、255 落，所以这 8 拍里线是"完全不存在"再重新出现——形成"线会消失"的心理预期，玩家在消失段前就开始预判下一段。

**尾杀频闪**：400→458 拍用 **4 拍一循环的 255 ↔ 170**（共 14 次），配合 180° 翻转，构成全曲的视觉高潮。注意频闪用 170 而不是 0——**保留 2/3 亮度**，线始终可见，不会让玩家丢失参照。

**收尾**：498→500 拍 255 → -1 淡出。

**可复用的 alpha 节奏表**：常态 32/8 呼吸 → 半透明段（127）→ 频闪段（170，4 拍周期）→ 淡出。每个段落用不同的 alpha 手法，视觉上立刻能分辨段落边界。


### scale 脉动与 color 轮换：段落视觉区分的低成本手段

《Desultory Signals》主线 L0 的 extended 事件里有 **scaleXEvents 99 段 + scaleYEvents 99 段 + colorEvents 25 段**，是"不换判定线也能看出段落变化"的关键。

**scale 脉动**：X/Y 缩放按 `1 → 1.18 → 1 → 1.18 …` 每 8 拍锯齿循环一次，即 **±18% 的持续呼吸式缩放**。判定线在原地微微胀缩，视觉张力明显但不移动落点——与 rotate 的 ±14° 是同一套"呼吸语汇"，两个通道配合出"线在呼吸"的观感。

**color 轮换**：每 24–36 拍换一个主色，过渡用 12 拍：

```
白 [255,255,255] → 淡蓝 [120,200,255] → 橙 [255,180,120] → 紫 [200,140,255] → 粉 [255,120,160] → …
```

颜色按 `start=旧色 → end=新色` 在 12 拍内渐变（easing=1），再衔接到下一轮。**这是"段落视觉区分"最便宜的手段**——不用改音符、不用改判定线运动，只换颜色就能让玩家知道"进入新段落了"。做高密度谱时尤其值得，因为高密度段玩家无暇顾及线在动，色彩反而是更可靠的段落标识。


### 辅助线的完整生命周期：从屏外静止到登场、退场、复活

《Desultory Signals》的 L1（345 音）与 L4（99 音）是两条辅助线，完整生命周期如下（以 L1 为例）：

| 时间 | 状态 | moveX | moveY | rotate | alpha |
|---|---|---|---|---|---|
| 0 → 168 | **完全不存在** | 0 | **-800** | 0 | 0 |
| 168 → 175 | **7 拍进场**（ease=6） | 0 → -430 | -800 → 0 | 0 | 0 |
| 175 → 176 | 1 拍微调 | -430 → -400 | 0 | 0 | 0 |
| 176 → 179 | **3 拍急转** | — | — | **0 → 90°** | — |
| 176 → 250 | 工作 74 拍 | -400 附近 | 0 | 90° | **255**（176 拍突然全亮） |
| 250 → 252 | **2 拍淡出** | — | — | — | 255 → -1 |
| 252 → 367 | 消失 115 拍 | — | — | — | -1 |
| 367 → 368 | **1 拍淡入** | — | — | — | -1 → 255 |
| 368 → 400 | 再工作 32 拍 | — | — | — | 255 |
| 400 → 401 | 1 拍淡出 | — | — | — | 255 → -1 |

**可直接复用的要点**：

1. **屏外锚点用 -800**，比屏幕下缘 -450 更远——辅助线"完全不存在"的状态必须彻底，否则玩家会看到一条莫名其妙的线；
2. **进场用 7 拍 + ease=6 (Sine InOut)**，从屏外下方同时升起并滑到位——玩家有足够时间把视线移到新线；
3. **入场后 3 拍急转到 90°**，让线成为一个明确的"斜向参照系"，而不是一条没方向的横线；
4. **alpha 从 0 直接跳到 255**（1 拍）在工作段开始时——线不是"淡入"的，是"亮起"的，配合它 74 拍后突然消失，形成"闪现"感；
5. **退场 2 拍淡出到 -1**，然后消失 115 拍，再 1 拍淡入复活——**辅助线不必全程在场**，让它有缺席反而是演出；
6. **辅助线的音符 X 只在 ±280**（贴着线走 ±0~±280），主线才用满 ±620。分工明确：主线负责复杂图案和大跨度，辅线负责局部补充与视觉呼应。
7. 辅助线的 speedEvents 拆成 140 段（每 1–2 拍一段，恒定值）——长时间静止的线需要持续声明流速，否则会因流速归零出现"音符贴线"。


### 镜像对是同刻对称进场、之后各自演化

《Desultory Signals》的 L1 与 L4 是一对"左右镜像"的辅助线，但**不是全程锁定镜像**。

**实测**：

- 两条线的时间轴完全一致（同拍进场、同拍退场），moveX 在前 11/45 段满足严格取反镜像（L1 → -430，L4 → +430）；
- 从第 300 拍起两条线分道扬镳：L1 的 moveX 走 -160 → +199 → -400，L4 走 +160 → -211 → +400；moveY 与 rotate 的相位也开始错开（L1 rotate -13.9°，L4 rotate +10.9°）；
- alpha 时间轴也各不相同（L1 在 175/176/250/252/367/368/400 处切换，L4 在 303/304/336 处切换）；
- 音符分工：L1 只做双押（345 音，最大同拍 2 音），L4 同样只做双押（99 音）。

**结论**：镜像对的正确用法是**"同一时刻对称进场、给出对称的第一印象"**，之后两条线各自独立编排、各自演化。做成全程锁定的机械镜像反而呆板（等间距率 57%，等于一条机械复制品）。

**分工公式**：主线承载 88% 的音符（3192/3636）并用满 X 范围；两条辅线合计只 12%，全部是双押，X 限制在 ±280 以内。**主辅线的物量比约 7:1 是成熟配比**，辅线是"视觉与节奏的呼应"，不是第二个主线。

## 四、谱面结构与情绪流

### 4.1 段落类型

| 段落 | 设计要点 |
| --- | --- |
| 前奏 Intro | 引入与热身，常用 Drag 或低密度 Tap，配判定线缓慢移动定调 |
| 预副歌 Build-up | 密度渐升，判定线摆幅加大，视觉"收紧再释放" |
| 副歌 Chorus | 密度峰值（NPS 最高），常配多线、垂直判定、密集纵连与双押 |
| 间奏 Break | 爆发后强制降密度（可降至 20%），纯长条或纯 Tap，让肌肉恢复供氧 |
| 尾杀 Outro | 末段收束，可为极高密度也可为极简连续点击 |

**Build-up 到 Chorus 的"释放点"**：

**Break 段的常见错误**：放入"低密度的复杂机制"（如慢速倒打或轴交互），以为密度低就是休息。但低密度复杂机制的**认知负荷可能高于高密度简单纵连**。真正的呼吸段应是**机制简单 + 密度低 + 采音清晰**。纯 Tap 或纯 Hold 的直线排列是最安全配置。

**尾杀的两种思路**：

- **密度收束型**：NPS 从 Chorus 峰值继续攀升，用极密纵连或交互终结，考验体力
- **精准收束型**：密度骤降，留下几个间隔较大、需精准击打的音符（连续 Flick 或大跨度阶梯），考验心理素质

高定数谱面通常选精准收束型——在体力耗尽时保持精准比继续连打更难，"最后几个音打飞"的挫败感远强于"最后一段没力气"。

### 4.2 密度模型

**NPS（Notes Per Second）**：

**波浪模型**：密度曲线应呈波浪状，推荐 `[低 → 中 → 低 → 高 → 中 → 低 → 极高 → 低]`。绝对避免长时间维持最高 NPS，否则变成纯体力测试。

**数据化表达**：实用工程习惯是每隔 8 拍或 16 拍统计该段平均 NPS，与情绪曲线对照。若发现"应该轻松"的段落 NPS 高于"应该激烈"的段落，说明采音选择出了问题——可能把背景音中的密集碎拍全采成了 Tap。

**采音分层三优先级**（控制密度的核心手段）：

| 层级 | 内容 | 音符类型 | 处理 |
| --- | --- | --- | --- |
| 第一层 必采 | 底鼓、军鼓、主旋律重音 | Tap / Hold | 占据判定线主要位置 |
| 第二层 选择采 | hi-hat、镲片、旋律装饰音 | Drag / 副线 | 填充视觉密度但不增加操作压力 |
| 第三层 氛围采 | 环境音、混响尾音、持续铺底 | Hold / 极低透明度表演线 | 暗示而非要求操作 |

**当第一层采音已导致 NPS 过高时，第二层应果断舍弃**。玩家节奏感知主要依赖第一层，第二层缺失不破坏音乐体验，但第一层过载直接摧毁可玩性。

---

### 4.3 打击感的数据层面设计

不碰音效文件的前提下，谱师能不能通过谱面数据影响玩家的"打击感"？可以，但手段是**音符类型的选择、排列密度、以及音符与判定线的空间关系**。

**音符类型本身就是反馈信号**，且内建于游戏引擎，不依赖资源包：

| 类型 | 反馈性质 |
| --- | --- |
| Tap | 需精准点击，窗口最窄，击打有明确"确认感"——打击感最强 |
| Drag | 触碰或划过即可，无精准确认感，但提供"流畅滑过"的连续感 |
| Hold | 按下并保持，反馈是"持续的控制感"而非"瞬间的确认感" |
| Flick | 快速滑动，反馈是"甩出去"的释放感 |

**控制手段**：需要强调重拍时用 Tap 或 Flick；表现连续流动段落用 Drag；表现持续音或压迫感用 Hold。**同一段音乐用 Tap 写和用 Drag 写，玩家感受到的"打击存在感"完全不同。**

"黄键海"的社区讨论提供了一个具体案例：黄键判定声音能辅助 bass 更好听，官谱里黄键尾端指向的地方更可能出现 note，也起到引导手序的作用。关键不是黄键本身的音效（那可被替换），而是**黄键的排列形成了视觉和手序上的引导**——玩家看到一连串 Drag 的尾端指向某方向，会自然把手移过去，为下一个 Tap 做好准备。这是通过数据布局实现的"预期管理"。

**密度曲线就是"手感曲线"**。玩家对打击感的感知很大程度取决于**相邻音符之间的时间间隔变化**：

- 全程 8 分直线排列 → "平稳但无聊"
- 从 4 分压缩到 16 分再回 4 分 → "紧张然后释放"
- 全程 16 分但中间插一个空拍 → "被掐住呼吸然后喘了口气"

第四卷的波浪模型本质就是一套**通过密度变化制造情绪起伏的工程规范**。违反它，玩家感受到的不是"难"，而是"累"和"困惑"。

**具体控制点**：判定线剧烈运动的段落要适当降低音符密度。判定线运动会分散视觉注意力，此时密度仍高，玩家陷入"看线还是看音符"的困境。降低密度不是放水，是**让认知资源能分配给判定线运动本身**，从而在视觉层面获得"演出感"而非操作层面的"窒息感"。

**音符与判定线的空间关系作为手感变量**：

| 组合 | 手感 |
| --- | --- |
| 判定线静止 + 音符密集 | 视线有稳定锚点，专注音符本身，纯节奏挑战 |
| 判定线缓慢平移 + 音符稀疏 | 视线跟随线移动，音符从远处飘过来，流动、环境化 |
| 判定线快速旋转 + 音符密集 | 视线在旋转坐标系中追踪，混乱、需高度集中；持续过久会从"紧张"滑向"疲惫" |
| 判定线在音符飞行途中变速（快慢刀） | 视觉判断与判定时刻脱钩，被欺骗感；适合短促有明确鼓点支撑的段落 |

**控制手段**：写每一个音符前先问"这条判定线此刻在做什么"。判定线正在剧烈运动时，该音符应更稀疏、更靠近屏幕中央、更倾向 Drag 或 Hold；判定线稳定时可放心用密集 Tap 和精准配置。

**伪音符是被低估的工具**。`isFake` 允许放置不参与判定的音符——屏幕上正常显示（除非用透明度隐藏），但不产生判定也不触发打击音效。**核心用途不是"骗玩家"，而是控制视觉密度与操作密度的比例**：主导层写成真实音符，次要层写成伪音符放在副线或表演线。玩家看到密集视觉信息、感受到音乐丰富性，但手指只需处理主导层。**视觉密度与操作密度被解耦。**

合理性在于：玩家节奏感知主要来自听觉，视觉上的密集音符不会误导他们击打不存在的音——伪音符没有判定，打上去也无反馈，几次之后玩家就会学会忽略它们。

**伪音符滥用的警戒**：会制造"虚假期待"。如果玩家看到密集视觉音符却发现只需打一小部分，可能感到"被戏弄"。**原则：伪音符应出现在玩家"预期不需要操作"的位置**——远离判定线的远处、副线的装饰性运动轨迹、透明度较低的背景层。伪音符若出现在主线判定区域正中央，玩家会本能尝试击打，打不到就产生挫败感。

**本节核心结论**："打击感"在数据层面的本质是玩家对"我的操作是否被系统正确接收"的确认感，来自三处：①音符类型与音乐情绪匹配；②密度变化与认知资源匹配；③视觉信息与操作要求匹配。写每个音符时问自己三个问题：**这个音符的类型对不对？这个位置的密度合不合适？玩家看到这个音符会不会误以为需要打它？**


### 段落密度要有真实峰谷，尾杀对准音频 RMS 峰值

密度必须做出**真实峰谷**，而不是"全程高位偶尔降一点"。实测标尺：把一张谱的密度峰谷比从 1.9x 提到 7.5x 之后，最直接的观感变化来自"终于有了喘气的地方"。

**做法**：

1. 先用音频 RMS 包络找音乐的真实高潮区，不要凭听感估计：对整轨按拍窗口算 RMS，峰值区间就是该放尾杀的位置；
2. 尾杀必须放在**音频最响的段落**，且是全曲密度最高的段落。实测案例：音频 RMS 峰值在 416–452 拍（rms 0.40），而谱面 436 拍就开始"降阶"，把音乐最猛的地方浪费掉了；改成 420–452 拍做尾杀（9.8 音/拍）后，全曲密度峰谷比达到 19.2x；
3. 尾杀前留一个 4 拍左右的**空段/归位段**（视觉清场、翻转归位），"猛"要有对比才成立；
4. 休息段不能只写"密度低"，要真的稀疏 + 简单机制 + 长音（Hold）。低密度段配复杂机制，玩家依然读不懂。

**量化**：以 15 拍为窗口统计全谱音符数，峰谷比低于 3x 的谱面基本没有情绪流；成熟谱通常在 10x 以上。


### 节奏变奏：等间距十六分是机械流水的量化指标

"单调"可以被量化。统计相邻音符的时间间隔，**间隔恰好等于十六分音符的比例**是机械流水程度的直接指标。

**实测**：自造谱面 75% 的相邻音距恰好是十六分（连续 1000+ 音），视觉上就是一条匀速的"音符传送带"，定数再高读起来也像流水线。加入段落级节奏变奏（每 4 小节换一次槽位变体）后，该比例降到 4.3%。

**做法**：

- 每个段落定义 3–5 个节奏槽位变体，按小节轮换。16 分的变体可以是 `[0,.5,1,1.5,2,2.5,3,3.5]` / `[0,.5,1,2,2.5,3,3.25,3.75]` / `[0,.25,.75,1.25,2,2.5,3,3.5]` / `[0,.5,1.25,1.75,2,2.5,3,3.75]`；
- 变奏要保留段落的"性格"（同一段落的所有变体共享重音位置），只改细节密度与切分；
- 判定口径：**任意 16 拍窗口内等间距比例 > 50% 就应该重写**。

**配套**：单一 X 图形循环也是单调源。段落之间换 X 图形库条目（阶梯/波浪/扇形/聚散/交互/扫动/之字），比单纯加密度更能改变读谱体验。


### 高密度谱的音符配比标尺：NPS 24.5 / Drag 三成 / 同拍六押

《Desultory Signals》（AT Lv.18.2 / BPM 202）的音符侧实测数据，可作为高密度谱的配比标尺：

| 项目 | 实测值 | 说明 |
|---|---|---|
| 总音符 / 时长 / NPS | 3636 / 148.4s / **24.51** | 高密度谱的 NPS 量级参考 |
| Tap | 57.4% | 仍是主体 |
| **Drag** | **33.5%** | 高难度谱的 Drag 可占到三分之一 |
| Hold | 6.8% | 但时长只有 **0.2~2.5 拍，均 0.6 拍** |
| Flick | 2.3% | 占比很低 |
| 同拍最大音数 | **6 音** | 多押分布 {2:167拍, 3:125拍, 4:45拍, 5:14拍, 6:156拍} |
| 密度曲线（16 拍窗） | 54 ~ 174 | 峰谷比 **11.6x** |
| L0 等间距 16 分率 | **4.3%** | 主线高度变奏 |
| 辅线等间距 16 分率 | 57% | 辅线反而规整 |

**三条与常识相反的经验**：

1. **Hold 可以极短**。均 0.6 拍（约 0.18 秒）的 Hold 是"点住一下就松手"的连击式短押，不是长音。Hold 用作节奏重音与打击感，而不是"持续的音"。真正需要持续音时才写长 Hold。
2. **Drag 可以是主力机制**，占到 33.5%。此前"Drag 只用于真滑音"是低难度谱的规则；在 AT18 级别，Drag 是"用位移代替点按"的核心表达方式（交替流、双向扫动、边线横移）。**Drag 的占比应随定数上升**，低定数用 3% 是对的，AT18 用 33% 也是对的。
3. **多押可以到 6 音**。同拍 6 音（156 拍）在这张谱里是常规配置，前提是 X 分散在 ±620 全域。**"同拍上限 3"是低难度谱的限制**，不是通用规则。

**密度与视觉高潮可以分离**：该谱密度峰在 224–240 拍（45%–48% 处），而视觉高潮（180° 翻转 + 4 拍频闪）在 364–458 拍（73%–92% 处）。**视觉高潮放在后段做"收束前的最后演出"，密度峰放在中后段**，两者不必重合。

## 五、采音哲学与配置逻辑

前四卷讲"怎么做"，本卷讲"为什么这么做"。**打击音效、视觉特效、资源包外观都不是谱师能控制的**——玩家可以替换 click.ogg、可以用着色器覆盖视觉设计、可以在设置里关掉打击特效。**谱师唯一能控制的是谱面数据本身：音符在什么时间、什么位置、以什么类型出现，以及判定线如何运动。**

### 5.1 堆叠式写谱法的根本局限

经典"堆叠式写谱法"：有什么音就写什么配置，两音叠一起同时表现两个音，三音叠一起同时表现三个音，长音必拉 LN，有鼓必双押。社区批评精准指出这种思路"不是绝对不行，但非常难写出彩"。

**根本原因是轨道资源有限**。以 4K 为例，一段碎音安排成"必须两个 note"，同时又要表现小提琴，押数变三押；还想表现别的声音就变四押。RPE 多线体系同理：判定线的音符容量、玩家手指数量、读谱带宽都有限。**试图表现一切，结果什么都表现不好。**

新手谱师的两个核心问题是"音采满"和"不敢放开来采"——前者指 0.5 倍速一点点听把所有鼓点都采成 Tap；后者指采完只会排键，不合理地采人声和 bass。**共同根源都是把"采到更多音"误认为"采得更好"。**

### 5.2 主导层原则：只采最突出的声音

较成熟的采音思路：**尽可能以合适的方式表现出音乐中最突出的声音，其他不算明显的声音都是次要的，可按个人喜好合理舍去。**

采音本身是主观的，但核心逻辑一致——在当前时刻，你最想表现什么声音？以它为重点就足够了。

**但采音不能随意**。完全按个人想法想到什么写什么、忽略谱面结构，整张谱面会显得混乱，因此采音和舍音需要内在逻辑。纯音乐更容易把控（音色再丰富也总有明显主次），带人声的歌曲更难（人声与乐器"似乎都很重要"），需从可玩性、谱面结构、综合表现力多方面权衡。完全忽略人声和完全忽略乐器都显然不恰当。

**实用判断标准**：如果某时刻同时想表现三个声音，而这三个声音的轨道位置分配导致配置别扭或密度失控，**就只保留最重要的那一个**，另外两个通过舍音或视觉暗示处理。玩家的节奏感知主要依赖主导层，主导层的清晰度决定谱面的"合曲感"。

### 5.3 舍音的四级操作层级

结合第四卷采音分层框架，舍音按以下优先级执行。**这些操作完全在可控域内，不依赖外部资源或玩家设置。**

| 级别 | 手段 | 做法 |
| --- | --- | --- |
| 第一级 舍层内 | 密度过高只保留重拍 | 16 分鼓点段只采 8 分骨架。判断依据：哪些是鼓手真用力打的，哪些是手顺带碰到的，只采前者 |
| 第二级 舍层间 | 舍弃第二层 | 第一层（底鼓/军鼓/主旋律）已致 NPS 超出目标区间时，第二层（hi-hat/装饰音）果断舍弃。这一刀必须果断 |
| 第三级 类型替换 | Tap → Drag | Drag 容错高，可在保持视觉节奏呈现的同时降低操作压力。密集段作视觉填充用，关键重拍仍用 Tap |
| 第四级 视觉暗示 | 表演线假音符 | 用表演线音符或低透明度 Hold 暗示被舍弃的声音，不要求玩家操作 |

**第三级的警戒线**：过度使用 Drag 会导致"手感发虚"，玩家难以从打击反馈中获得满足感。Drag 的合理用量是密集段作视觉填充、关键重拍仍用 Tap。

**第四级的实现**：RPE 多线体系的独有优势。表演线音符通过 `isFake=1` 设为假音符，不参与判定但视觉呈现。你控制"这个假音符出现在哪里、什么时候出现"，玩家是否看到取决于其设备亮度和注意力分配——但**至少你提供了这个视觉信息**。

### 5.4 采音逻辑的一致性要求

社区反馈中反复出现对"一致性"的批评。osu! 谱面讨论指出钢琴长条的使用"要么都给，要么每组最后一个长音给，要么有规律或符合音乐的停顿"，而"给中间一根没看懂"的写法会让玩家困惑。

RPE 语境下同样原则：判定线的运动规律是否可预测、副线的使用是否有稳定功能分工、高密度段落的起始位置是否有视觉预告。**一致性不是要求每段一模一样，而是要求玩家能建立预期。**第一段用副线承载 Hold，第二段突然用副线承载高密度 Tap 而主线变装饰，玩家的认知模型就崩溃了。

**可参考的实践**："按结构分组采音"——以四屏、八屏或十六屏为一组，每组最后四分之一更换采音重点，每次都做出较明显信号。这种看似公式的逻辑对应歌曲段落间的细微区别，玩家多次游玩后会感知"每过一段就会有变化"的规律，从而在心理上做好准备。

### 5.5 可控域与不可控域

**你控制的**：

- 每个音符的 `type`、`positionX`、`startTime`、`holdTime`
- 每条判定线的 `moveXEvents`、`moveYEvents`、`rotateEvents`、`alphaEvents`、`speedEvents`
- 表演线的 `isFake` 设置和透明度事件
- 谱面整体密度曲线和段落结构

**你不控制的**：

- 玩家使用的打击音效资源包（他可以用任何 ogg 替换 `click.ogg`）
- 玩家是否开启打击特效、特效的持续时间与缩放
- 玩家是否使用着色器覆盖你的视觉设计
- 玩家的设备性能、屏幕尺寸、判定偏移设置

**这个区分的实际意义**：玩家说"这谱手感不好"时，判断问题出在你的可控域还是他的不可控域。他说"打击音效太难听"是资源包问题，你无法解决也不必改谱；他 说"这一段打起来发涩"可能是采音与判定线运动耦合出了问题，这是你需要检查的。

社区有一句话值得记住：**"pgr 是一款创意音游，特色就在判定线和 note 的表演，所以适当放弃一些鼓或人声留出休息段是正确之举"。舍音不是妥协，是设计。**你放弃的那些音，恰恰是让留下来的音变得清晰的代价。

### Drag 只用于真正的滑音：CQT 音高单调检测

Drag 是"弯曲的长条"，是滑音的操作表达，不是快速连段的替代品。把快速连段批量转成 Drag，玩家按住一根手指横拖就能全接，视觉爆表但零技术含量。

**适用范围（本条只针对低中定数谱）**：真滑音是 Drag 最典型的用法，但**高定数谱的 Drag 占比可以极高**——社区成熟谱《Desultory Signals》（AT Lv.18.2）实测 Drag 占 **33.5%**，用法是"用位移代替点按"（交替流、双向扫动、边线横移），而不是逐音对应音频滑音。**判据是定数与手法意图，不是 Drag 的绝对占比**：低中定数（≤AT16）应把 Drag 控制在 3% 以内、只用于真滑音；高定数谱则可以把 Drag 当主力机制，但要保证每个 Drag 段都有明确的位移意图（见「交替流的标准写法：幅度递增的左右交替 Drag」）。

**判定滑音的正确方法**：用 CQT 音高轨迹检测，而不是用音符间隔检测。

- 取 CQT（fmin 建议 C2，n_bins 60，bins_per_octave 12），在候选点 ±0.1s 窗口内取 argmax 频率并换算半音；
- **相邻采样的半音跨度 > 1.5** 才算真实滑音；
- 用音符时间间隔判断会误判：八分音符的间隔已经小于常见阈值，会把整段连判成滑音（实测曾导致 85% 的音符被标成 Drag）。

**工程约束**：

- 相邻 Drag 之间至少间隔 1 拍；
- 同一拍内 Drag 不得与其它音符同位，且相邻两音的 positionX 差值不得小于 60——否则视觉上又变成"连续的同 X 黄键"，等价于假纵连；
- 滑音的 Drag 应该沿滑音方向放置在跨度大的位置，并让前序手序自然把玩家导向它。

**反例**：整曲出现成片同位 Drag（连续 7 个以上、positionX 完全相同）＝玩家按一根手指全接，难度归零，属于必须修的反例。

## 六、工程化制谱规范

### 8.1 事件连续性原则

**绝不瞬移**：

**数学表达**：对任意判定线的任意参数（X、Y、Rotate、Alpha），在时间轴上必须满足**左极限等于右极限**。即前一个事件的 `end` 值严格等于后一个事件的 `start` 值。前事件结束于 X=300、后事件从 X=301 开始——60fps 下视觉几乎不可见，但**玩家的手指会感知到**。高密度段中这种微小不一致会累积成"手感发涩"，玩家说不出哪里不对，就是打不出 Perfect。

**贝塞尔斜率陷阱**：自定义贝塞尔曲线端点斜率不一定与前后事件匹配。即使数值连续，**速度**也会在连接处突变产生"卡顿感"。解决方案是连接处统一同类缓动，或在贝塞尔控制点中刻意匹配前后斜率。

**多线隔离**：用图层堆叠把副线压在底层，主线放顶层，防止音符视觉重叠误读。

### 8.2 手指物理与映射

**手序冲突 Hand Lock**：

**隔离原则**：主线做花，副线做稳。密集 Tap 放主线，短促 Hold 分配到垂直副线上。

**工程落地**：

- 主线 Tap 的 X 范围应尽量覆盖全屏，但**高密度段落的 Tap 应集中在中央区域**（X ∈ [-300, 300]），因为中央是双拇指最易到达处
- 副线（Hold/Flick）可放边缘（X > 400 或 X < -400），这类操作不需要快速连打，边缘反而避免与主线抢手指

**键盘映射量化参考**：全键映射下操作从"手指触摸"变为"手指按键"，单次击打力量消耗约为触屏的 2-3 倍。NPS > 20 时疲劳积累远快于触屏。标注"推荐触屏"或"PC 需注意体力分配"是对玩家负责的做法。

**最坏情况模拟**：假设玩家用双拇指，某时刻左手拇指正在执行 X=-400 到 X=-100 的快速滑移（耗时约 0.3 秒），右手拇指需同时完成三次纵连。若纵连 X 也在左侧（X < -200），右手拇指需跨越中线，物理上导致**双手交叉**，极易失误。

### 8.3 数据对齐与校准

**BPM 对齐**：

**精度问题**：RPE 通过 `startTime` / `endTime` 的 beat 值实现对齐，beat 精度通常 1/48 或更高，足以表达 32 分甚至 64 分音符。但**并非所有音乐的节奏都严格落在 BPM 网格上**——真实录音存在微小 timing 波动。强制对齐会导致"谱面节奏正确但听感别扭"。专业谱师处理方式：以 BPM 网格为骨架，对明显偏离网格的采音点**手动微调**，允许 ±5-10ms 偏移，这种"不完美对齐"反而能获得更好的音押手感。RPE 的 beat 系统支持小数。

**采音与判定线的耦合**：判定线本身运动时，音符的"视觉落点"与判定线实际位置可能偏差。例如判定线高速向右移动，音符在判定线到达某位置时与其重合，但玩家追踪的是音符而非判定线。移动过快时玩家可能在判定线到达前就点击。解决方法：在判定线剧烈运动的段落**适当降低音符流速**，让音符视觉飞行时间与判定线运动时间形成更宽容的重合窗口。

### 8.4 事件层结构

判定线对象包含 `eventLayers` 数组，每个 EventLayer 含五类普通事件数组：`moveXEvents`、`moveYEvents`、`rotateEvents`、`alphaEvents`、`speedEvents`。扩展事件（scaleX、scaleY、color、text、paint、incline）位于 `extended` 下。

**普通事件字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `startTime` / `endTime` | beat 数组 | 起止拍，`[整数, 分子, 正分母]` |
| `start` / `end` | 数值 | 起止值 |
| `easingType` | 整数 | 缓动编号 1-29 |
| `bezier` | 0/1 | 是否启用自定义贝塞尔 |
| `bezierPoints` | 四元数组 | 贝塞尔控制点 |
| `easingLeft` / `easingRight` | 0.0-1.0 | 缓动边界裁剪 |
| `linkgroup` | 整数 | 绑定组，同组事件同步 |
| `inst` | 0/1 | 钩定首尾 |

**流速事件特殊性**：不支持贝塞尔曲线，仅支持预设缓动类型。RPE ≤1.6 缓动描述音符位置变化（导函数形状匹配），1.7.0+ 直接缓动速度数值。负流速时音符向上飞，Hold 尾部出现时整个音符瞬间完整显示，与本家 Phigros 不一致。

### 从零写谱的实战工程坑清单

以下都是实机踩过、且现成体检工具未必抓得到的坑：

1. **秒 → 拍换算方向**：`拍 = 秒 × BPM / 60`。写成 `秒 × 60 / BPM` 会把时间戳缩小 3.4 倍，全部滑音与事件错位到开头，视觉表现就是"开头堆了一串同位黄键"。
2. **遍历列表时往同一个列表 append**：分线时若 `main = made` 是别名再往 `main` 追加，密度会失控（实测超出目标 2.6 倍）。复制用 `list(made)`。
3. **派生字段**：`numOfNotes` 由工具在写入时同步；手写 JSON 改谱面会让它停留在旧值（实测 [2196,500,512] vs 实际 [1410,172,113]），导出后字段与内容不符。
4. **`isCover` 语义**：`isCover=1` 表示"覆盖墙"，其音符被判定线扫过后不再显示；**同一 group 内多条 isCover=1 的线会互相遮挡**。常规演奏线一律用 0（社区成熟谱 8 条线全为 0）。
5. **判定线 X 摆幅与音符 X 的叠加**：moveX ±250 叠加音符 X ±540 会超出 ±675。线摆幅要按音符 X 的实际范围反推。
6. **`RPEVersion ≥ 163` 时父线旋转默认传递给子线**（rotateWithFather 未定义时），< 163 则不传递；社区成熟谱常见 150，RPEN 新建默认 170，改版本号会改变旋转表现。
7. **工具的写入命令会自动保持事件数组升序**（合并后重新排序），所以"事件数组乱序"这种致命问题几乎只来自手写 JSON——一旦手写，必须自己排序并回读校验。
8. **段间值必须首尾相等**：moveX/moveY 相邻段 end ≠ 下一段 start 时，判定线会瞬移（可用 easingType=6 Sine InOut 在过渡段内连续插值）。
9. **过渡段不要做细分子步长**：把一段长事件按 0.5 拍切成上百段，段数会从 32 膨胀到 300+，且后段永远不触发。只按设计窗口边界切分。
10. **改循环结构后必须回读体检结果**：自写检查通过不代表没问题——实测曾出现自写检查全绿、而 diagnose 报 9 处"事件时间重叠"（屏外分支写成独立 for 循环，段被追加两次）。


### 多押必须在分线之后展开

固定多押在"生成阶段"写死、再分线，是纵连类缺陷的头号来源。

**故障链**：生成阶段固定三押 [-400,0,400] → 分线到 3 条判定线 → 每条线每拍只剩 1 个音 → 主线变成连续几十个 positionX=-400 的同 X 纵连（质量检查报 98 项），难度不升反降。

**正确顺序**：

1. 先分线（把音符按负载均衡分配到各线），不要在分线前定死多押；
2. 分线后，对同一线同一拍的 ≥3 音展开成对称多押：三押 `[c-d, c, c+d]`、四押 `[c-1.5d, c-0.5d, c+0.5d, c+1.5d]`，中心 c 随拍流动；
3. 加"同位约束"：同一判定线上相邻音符的 positionX 差值不得小于 60，冲突时依次尝试偏移 90/180/270/360，仍冲突则丢弃该音。

**三押 X 的选择**：对称值 [-400,0,400] / [-520,0,520]；四押 [-480,-160,160,480]；五押 [-520,-260,0,260,520]。多押的 X 跨度要落在 ±620 以内，配合判定线 moveX 摆幅后仍在 ±675 内。

**多押的归属**：多押是"同时按下"的手部负担，一拍最多 3 个音符（含主音）。超出说明密度分配器超载，应减密度而不是放宽上限。

| --- | --- | --- |

| Lv.16-17 | 进阶玩家挑战区 | 机制开始复杂（倒打、垂判），NPS 15-25 |
| Lv.18+ | 顶级玩家怪物区 | 常规底力 + 复合机制，NPS > 30，多线并发，坐标轴持续变换 |

### 8.3 心理陷阱与伦理边界

| 陷阱 | 手法 | 合理边界 |
| --- | --- | --- |

## 九、判定线表演的可读性预算

判定线表演是 RPE 谱师最引以为傲也最容易翻车的领域。切入点不是"如何做出炫酷的效果"，而是**"玩家能承受多少视觉信息"**。着色器、多线、快慢刀本身不是问题，问题是它们消耗的**可读性预算**超出了玩家的认知带宽。而预算的消耗**完全由谱面数据决定**，与玩家用什么资源包、什么设备无关。

### 9.1 可读性预算的概念

玩家读谱能力有限。任一瞬间需要从屏幕提取：

- 下一个音符的**位置**（X 坐标，以及判定线旋转后的相对位置）
- 下一个音符的**时机**（距离判定线还有多远，流速多少）
- 下一个音符的**类型**（决定操作方式）
- 判定线本身的**状态**（是否在移动、旋转、变速）

这些信息总量超过玩家处理能力时，读谱失败就发生了。**可读性预算就是玩家在单位时间内能正确提取的信息量。**

**控制手段**（全部在谱面数据内）：

| 参数 | 预算消耗 |
| --- | --- |
| 判定线运动速度 | 越快，追踪线本身消耗越多 |
| 旋转角度变化率 | 越快，坐标映射计算越难 |
| 音符生成密度 | 密度越高，单位时间需处理的信息越多 |
| 音符类型混合度 | 同一时刻出现多种类型，玩家需切换操作模式 |
| 多线数量 | 线越多，视线需扫描的区域越大 |

### 9.2 可读性预算的分配原则

**原则一：判定线运动与音符密度不能同时拉满。**

判定线剧烈运动时，玩家的认知资源大量用于"理解判定线在哪里、朝向哪里"。此时音符密度也高，玩家没有足够资源处理每个音符的落点和时机。**方案**：剧烈运动段落降低密度，或用 Drag 替代 Tap（Drag 对时机要求更低，消耗预算更少）。

**原则二：同一时刻的视觉信息源不超过两个。**

屏幕上有三条判定线同时运动、每条都有音符、还叠加着色器，玩家不知道该看哪里。**方案**：任何时刻让玩家清楚知道"现在应该关注哪条线"。主线保持稳定或可预测的运动，副线在不需要关注时降低透明度或移出主要视野。多线的功能分组（第六卷 6.2）正是为此目的。

**原则三：视觉预告必须存在，且必须被玩家看到。**

轴交互和倒打难，因为玩家需在大脑中重建坐标系。判定线在音符出现后才开始旋转，玩家可追踪音符规避；判定线在音符生成前已完成旋转并稳定，玩家只需适应新轴向。最恶劣是飞行途中持续旋转且毫无预告。**方案**：在需要玩家适应新轴向的段落之前，让判定线提前到位并**停顿至少一拍**。这个停顿就是视觉预告，消耗预算很少，但为玩家节省大量认知资源。

### 9.3 着色器效果的可读性代价

着色器（通过 extra.json 的 effects 字段）可实现色差、故障、模糊、扭曲。视觉冲击力强，但**直接消耗可读性预算**。

- 色差让音符边缘模糊，玩家需更长时间辨认音符类型和位置
- 故障造成画面随机偏移，破坏对音符运动轨迹的预判
- 模糊直接降低音符辨识度

**控制手段**：着色器参数（chromatic 的 power、sampleCount）可随时间变化。**音符密度高的段落把强度设为 0 或极低值；Break 段或 Intro 段拉高。**着色器是氛围工具不是信息工具，最佳位置是玩家**不需要精确读谱**的段落，而非 Chorus 高密度段。

**需警惕的工程问题**：着色器通过 extra.json 实现，**该文件不在 RPE 谱面 JSON 中**。分享谱面时遗漏 extra.json，着色器效果完全丢失。这不由谱面数据控制，但可在谱面描述中注明"本谱面使用着色器效果，请确保 extra.json 与谱面文件一同导入"。

### 9.4 快慢刀的可读性边界

快慢刀本质是**欺骗玩家的视觉判断**。判定时刻不变，视觉飞行速度变了。玩家若根据"音符看起来快到了"判断击打时机就会失误。

**可读性代价**：迫使玩家从"目押"切换到"音押"。采音足够清晰（鼓点明确、节奏骨架可辨）时玩家可靠听觉规避；采音不清晰（旋律复杂、碎拍多、人声与乐器交织）时，快慢刀就变成"只能靠背谱"的恶意设计。

**控制手段**：使用前检查该段采音是否符合第四卷的"第一层必采"标准。底鼓军鼓节奏骨架足够清晰则安全；玩家无法通过听觉判断时机就不要用，或在该段之前用视觉预告（如判定线短暂停顿）提示"这里要变速了"。

**易被忽略的点**：流速事件不支持缓动类型，流速为负值时 Hold 视觉行为异常（尾部出现时整个音符瞬间完整显示）。在需要精确松手的 Hold 段落，保持流速稳定。

### 9.5 多线系统的可读性管理

多线最具表现力，也最容易摧毁可读性。

**第一原则：任何时刻玩家只需关注一条线。**

- 主线承载高密度 Tap 时，副线应处于低透明度或远离主视野
- 副线承载需要操作的 Hold 时，主线应暂时降低活动量
- 表演线可随时运动，但**不能遮挡玩家需要读取的音符**

**具体数据操作**：

- 用 `alphaEvents` 控制各线透明度：主线始终高透明度，副线需要操作时提高、不需要时降低，表演线保持低透明度或完全透明（只显示其上的音符，不显示线本身）
- 用 Z-Order 层级：主线最上层，副线中层，表演线底层。音符视觉重叠风险由层级顺序控制
- 用 `isFake` 将纯视觉音符放在表演线上，确保不与主线真实音符视觉混淆

"56 条线"的极端案例说明：线的数量本身不是可读性的决定性因素，**线的功能分工是否清晰才是**。56 条线全部无规律运动且承载真实音符是灾难；3 条线承载操作、53 条线只做背景视觉运动且透明度极低，玩家甚至可能注意不到那 53 条线。

### 9.6 本章核心结论

判定线表演的边界不是"技术上能不能做到"，而是**"玩家能不能在做到的同时还能打谱"**。

RPE 中可以实现任何视觉效果：线飞出屏幕外再飞回、旋转 720°、透明度闪烁、流速骤变、多线交织。但每个效果都在消耗可读性预算，而**消耗量由谱面数据决定**。写事件时问自己：

- 这个运动是否影响了玩家对音符位置的判断？
- 这个旋转是否让玩家需要重新计算坐标系？
- 这个变速是否让玩家无法通过音乐判断时机？
- 这条线的透明度是否让玩家把它误认为主线？

若任一答案为"是"，而你又没给足够视觉预告或密度缓冲，玩家感受到的就不是"演出"而是"干扰"。

**最终原则**：判定线表演的目标是让玩家在**打完谱之后**回忆起来觉得"这段演出很酷"，而不是让玩家在**打谱过程中**因为演出而失误。前者是设计，后者是事故。两者之间的界限，就是可读性预算。

### 判定线表演的动作预算：快速到位后停住

判定线的旋转只允许两种形态：**静态 0°**，或**短时间急转至固定角后长时间停住**。禁止全曲持续缓慢旋转——持续旋转会让音符落点坐标在玩家视野里持续漂移，读谱与操作分离，玩家只能慌乱追线。

**做法**：

- 旋转事件用"急转段（2–4 拍）+ 保持段（≥20 拍）"的组合，缓动用 easingType=6（Sine InOut），转速高、到位即停；
- 每一段旋转都要有明确目的（倒打、翻转、镜像、换轴），不要为了"动"而动；整曲只做一种慢速滚轴等于没做演出；
- 翻转的过渡窗口与旋转用同一时间窗（边翻转边升降），先跳位再转会让人失去方向感；
- 判定线剧烈运动的段落要降低音符密度——不是放水，是把认知资源留给读线本身。

**审稿口径**：遍历全谱 rotate 事件，若存在持续超过 8 拍且角度变化量超过 45° 的连续区间，判为违规，应改为"急转 + 停住"。

## 十、具体曲目逐段拆解——机制范本

第九章确立了可读性预算的抽象边界。本章把抽象原则落到具体谱面上：那些被社区反复讨论的段落究竟怎么组织机制？密度曲线长什么样？哪些被称"好"，哪些被骂"卡手"？

**本章定位是"范本库"，不是"抄写模板"。**每段拆解都附"这个设计解决了什么问题"和"在什么条件下会翻车"两个判断，供 AI 做类比推理。

### 10.1 《混沌入口》IN 16.8：轴交互作为核心机制

社区反复提及的"轴交互教科书案例"。TapTap 玩家的 AP 记录显示，难点高度集中于特定段落，而非全程均摊。

| 段落 | cb 范围 | 核心机制 | 玩家反馈 |
| --- | --- | --- | --- |
| 第一段拆谱交互 | 222–269 | 拆谱 + 左起手不顺 | "有时候会点歪" |
| 三段轴交互 + 混合交互 | 338–380 | 判定线旋转后的音符排列 + 短长条与蓝键混合 | "左手定位过弱，采用右手切、左手处理短长条" |
| 卡手段落 | 380–454 | 密度与手序的组合压力 | "打得很卡手" |
| 高难拆谱交互 | 776–824 | 与第一段同构但难度更高 | "采用 4k 手法缓解" |
| 十六段轴交互 | 834–935 | 连续轴交互 | "看懂了就基本没掉过" |
| 卡手 + 黄键 | 935–1004 | 黄键（Drag）未拉到位导致掉 | "经常没拉到位" |

**轴交互的设计逻辑**：338–380 段之所以被社区接受，关键在于**每段轴交互的起始是可预测的**。玩家提到"第一段轴交互为左起手"，说明判定线在音符生成前已完成旋转并稳定在确定轴向，玩家只需适应"左手先动"而非"猜测线会转到哪里"。这正是第九章原则三的正面案例。

834–935 的"十六段轴交互"被描述为"看懂了就基本没掉过"，进一步印证：**一旦玩家建立了"这一段就是连续轴交互"的心理模型，后续旋转就不再消耗额外可读性预算**，旋转本身变成预期内的信息而非意外。

**翻车边界**：若判定线在音符飞行途中持续旋转（而非生成前到位并停顿），玩家认知资源会被同时用于"追踪旋转中的线"和"判断音符落点"，可读性预算会在两三个音符内耗尽。338–380 段之所以可玩，恰恰因为每段轴交互之间**有稳定的间隙**，玩家可在间隙中重置视觉锚点。

### 10.2 《混沌入口》卡手段落：密度与手序的耦合失败

380–454 和 935–1004 两段被同一玩家描述为"卡手"，但原因不同。这是理解"卡手"与"难度"区别的关键案例。

**380–454：密度耦合问题。** 玩家说"打的很难受，感觉比较卡手"，但没指出具体机制失败。结合上下文，这段紧接在三段轴交互之后，玩家手部状态已从"旋转坐标系适应"切到"常规排列处理"，但密度没给足够缓冲。**这不是配置错误，而是密度曲线与机制切换的节奏不匹配**——轴交互段消耗大量认知资源，紧接着的高密度段落没给"喘一口气"的窗口。

**935–1004：黄键（Drag）的视觉引导失败。** 玩家明确指出"黄键经常没拉到位导致掉"。Drag 判定是触碰或划过即可，容错很高。但"没拉到位"意味着手指**根本没到达 Drag 所在位置**。通常因为前一串音符的手序把手指带到了远离 Drag 的区域，而 Drag 的视觉呈现不足以引导玩家在判定前把手移过去。

**可迁移的教训**：Drag 不是"放上去就自动打"的万能填充。Drag 放在需要大跨度移动的位置时，实际变成**定位测试**而非操作缓冲。若前序手序把双手锁在屏幕左侧，右侧的 Drag 就需要额外视觉预告（如 Drag 尾端指向或前置引导音符）让玩家提前移动。

### 10.3 《Message》AT 16.5：噪域与"不可见"作为演出

《Message》是第九章后篇引入噪域机制后的代表性曲目。**AT 难度物量仅 777，低于 IN 的 886，这在 Phigros 中极为罕见。**物量低于低难度谱面，意味着 AT 的设计重心不在密度，而在**机制的信息密度**。

**噪域的核心约束**：日文 wiki 明确指出"在这个区域里敲击音符不会产生判定，要有垂直判定的意识"。噪域不是"隐藏音符"，而是**在特定区域内判定被禁用**。

AT 谱面的关键设计：**噪域不是随机散布的障碍，而是与音乐结构同步出现的视觉元素**。谱面最后用噪域拼出 Geopelia 的蝴蝶发饰，说明噪域承担的是**叙事功能**而非纯难度功能。玩家需要"读懂"噪域的位置和含义，而非单纯"避开"它。

**噪域与可读性预算的关系**：噪域消耗的预算与其他机制不同——判定线运动消耗"追踪线位置"，快慢刀消耗"判断时机"，噪域消耗"判断哪里能打、哪里不能打"。当噪域与高密度音符同时出现，玩家需在每个音符到达前做二元判断（这个位置有效吗？），累积成本极高。因此《Message》AT 物量压到 777，本质是**用低操作密度换取高认知密度**。

**AT 的另一个可迁移设计**：暗转后光从中心扩散的段落，"光与暗的下侧边界线处所有判定都会发生"，玩家被明确告知判定发生在边界线上而非光区域内。这是**规则告知型机制**的典型：机制本身不复杂，但不告知玩家会在错误位置击打。RPE 中实现类似效果可通过表演线透明度变化或前置段落的视觉暗示来"教会"玩家规则，而非依赖玩家阅读 wiki。

### 10.4 《Desultory Signals》IN 17.0：底力谱的定位与耐力管理

《Desultory Signals》IN 17.0 是 Phigros 中首张、也可能唯一一张 IN 17 级谱面。社区评价高度一致：**底力要求极高，长时间高速连点 + 大位移黄键**，对耐力和定位都有高要求。

**难点分布数据**。一位 AP 玩家的逐段记录显示难点高度分散：

| cb 范围 | 难点性质 |
| --- | --- |
| 59–269 | 定位问题（蓝键点歪） |
| 269–349 | 节奏问题（跳拍 + 短长条） |
| 721–763 | 节奏 + SV |
| 763–856 | 节奏 + 漂移蓝键 |
| 866–912 / 979–1004 | 频繁采用"4k 手法缓解位移压力" |

**几乎没有一段被描述为"纯底力"或"纯读谱"**，每一段都是底力与读谱/定位/节奏的复合。

**"4k 手法"的含义**：指将原本设计为双指处理的配置，临时切换为多指分工（左手处理单点、右手处理长条），以缓解位移压力。**这说明谱面的排键在双指极限附近徘徊**——设计上可能双指可解，但双指解法的容错窗口极窄，玩家被迫寻找多指逃课。

**可迁移的教训**：17 级谱面的难点不应集中在"手指速度"单一维度。《Desultory Signals》的 17.0 定数之所以被接受，是因为难度来自**多个维度的叠加**（定位 + 节奏 + 耐力 + SV 读谱），而非单一维度极端化。只有极快纵连的谱面可通过纯底力训练解决；每段都在不同维度施压的谱面需要同时提升多项能力，定数提升才有说服力。

**翻车边界**：1126–1148 段"整体通过率非常低"，1874–2019 段"非常恐怖的位移，很容易漏，用不出什么手法"。共同特征是**位移幅度超出双指舒适区上限，且没有提供多指解法的引导**。设计大位移段时应问：这个位移在双指配置下，手指是否有足够时间从上一个位置到达下一个位置？如果没有，是否提供 Drag 或 Flick 作为柔性过渡？

### 10.5 正面范本的可迁移性规则

**规则一：机制切换必须伴随密度缓冲。**《混沌入口》的轴交互段之间、轴交互段与常规段之间，都存在密度的短暂下降。机制切换发生在密度峰值处时，玩家认知资源会被同时消耗在"理解新机制"和"处理高密度"上。**在每个机制切换点前 4–8 拍将 NPS 降至该段平均值的 60% 以下。**

**规则二：Drag 的定位引导优先于其填充功能。**Drag 不是"随便放哪里都能打"的音符。Drag 放在需要大跨度移动的位置时，前序音符的手序应自然将手指导向 Drag 方向。**放置 Drag 时应检查前 2–4 拍内是否有音符将玩家的手"带离"Drag 所在区域**；若有，应在 Drag 之前插入指向性过渡音符或调整 Drag 位置。

**规则三：低物量不等于低难度，但高认知密度需要明确的规则告知。**《Message》AT 用 777 物量承载噪域认知负荷，但前提是噪域规则在谱面内（或通过前置演出）被玩家理解。**机制无法通过视觉自解释时，应在描述中标注"需要阅读机制说明"或在前置段落设置教学性的简单配置。**

《Desultory Signals》（打打だいず？作曲 technoplanet，谱师 ye，AT Lv.18.2，BPM 202，RPEVersion 150，offset 0）是本项目的**成功谱标尺**。以下为全参数实测，可直接作为写谱时的对标基准。

**骨架**：`judgeLineGroup = ["Main"]`；8 条判定线但只有 3 条有音符（L0 主线 3192 / L1 345 / L4 99），其余 5 条为空占位；isCover 全 0；zOrder L0=50、L1=L4=40（主线压最上层）；blockAreaList 为空（不用噪域也能做出段落感）。

1. **判定线用"呼吸语汇"而不是"大幅动作"**：moveX ±199、moveY 中心 -300 振幅 ±45、rotate ±14°、scale ±18%——四个通道各自小幅摆动，合成"线在呼吸"的整体质感，落点坐标几乎不变。
2. **段长阶梯控制注意力**：0/2/4/8 拍四种段长分别对应锚点/微调/急转/保持，越想让玩家注意就越用短段 + 长保持。
3. **段落区分靠 alpha 节奏 + color 轮换 + scale 脉动**，不靠改音符。高密度段玩家无暇看线在动，色彩是更可靠的段落标识。

## 十一、反例集锦与负面训练集——什么样的谱面数据是"坏"的

第十章提供正面范本，本章提供负面样本。**"好谱"的上限依赖审美判断，但"坏谱"的下限是可以数据化的。**以下反例均来自社区批评中带有具体位置、具体配置描述或可量化特征的案例。**AI 生成谱面后应逐条对照本章自检：触发任何一条，需要修改而非交付。**

### 11.1 堆料型反例：密度曲线的结构性失败

**特征：NPS 在长时间区间内维持峰值，没有真正的呼吸段。**

社区对"塞爆""赛豹""茶包"的批评指向同一工程问题：**密度曲线不是波浪形，而是高原形或单调递增形**。新手最常见的堆料模式：前奏低密度建立预期，从副歌一路高密度到结尾，中间没有 Break，或 Break 只有 2–3 拍（BPM 180 下不到 1 秒）。

**可量化检测标准（N1）**：以 16 拍为窗口统计 NPS。**若连续 3 个以上窗口的 NPS 都在该谱面最大 NPS 的 80% 以上，且其间没有低于 50% 的窗口，则属堆料区间。**合理的波浪模型应在任何 32 拍区间内至少有一个 NPS 低于峰值 50% 的窗口。

**具体反例模式**：一张被批评的谱面"1770cb 开始的那段同理"指向同一配置的重复使用而没有密度变化。**重复本身不是问题，重复而没有密度起伏才是问题。**若一段纵连首次出现时是 Chorus 峰值，第二次出现时仍以相同密度出现，而音乐已进入间奏或桥段，谱面的密度曲线就和音乐的情绪曲线脱钩了。

**AI 的修改策略**：检测到连续高密度窗口后，找到最近的音乐段落边界（鼓点稀疏处或旋律转折处），在该边界处插入**至少 8 拍的密度下降（NPS 降至峰值 40% 以下）**，即使这意味着舍弃该段的部分第二层采音。

### 11.2 排键型反例：人体工学的数据边界

**特征一：中央区域过载（N2）。**

"前半段基本堆在屏幕中间 1/3 的区域"，"手机上打手指都要搅在一起了"。手机端双拇指配置下中央区域（X ∈ [-200, 200]）是自然落点，**适度的中央集中是合理的**。但当高密度段落所有音符都在此区间且持续超过 8 拍时，双拇指物理空间不足以在不碰撞的情况下完成交替击打。

**检测标准**：统计连续 8 拍内 X 落在 [-200, 200] 的音符比例。**若超过 90% 且该段 NPS > 10，触发中央过载警告。**合理分布应在中央高密度段之间有向两侧展开的过渡音符（至少 20% 的音符在 X < -300 或 X > 300）。

**特征二：大位移无缓冲（N3）。**

《Desultory Signals》中"1874–2019 段非常恐怖的位移，很容易漏，用不出什么手法"。大位移在高难度谱面中是合理挑战，但**位移幅度与时间间隔必须匹配手指物理移动速度**。

**检测标准**：计算相邻两个需不同手处理的音符之间的 X 距离和拍数间隔。BPM 180 下 16 分音符间隔约 83ms。**若两个音符 X 距离超过 400 单位（约占屏宽 30%）而间隔小于 16 分音符，则双指配置下几乎不可能在不提前移动的情况下完成。**合理做法是在大位移之间插入一个 Drag（允许滑动触碰）作过渡，或将其中一个音符改为 Flick（允许快速划过而不需精准落点）。

**特征三：反手配置无预告（N12）。**

一张被批评的谱面提到"还有反手"。反手本身不是错误，但**出现在玩家没预期的位置会导致手序混乱**。若前 30 秒都是左右手分工明确的配置，突然在某拍要求左手去够右侧音符，玩家会在那一瞬间犹豫。

**AI 的修改策略**：在反手配置前 4–8 拍，通过明确的位置信号（左侧 Flick 或 Drag 引导左手向中线移动）预告"左手需要过来了"。无法提供预告时，将反手配置改为双押或拆分为两个 Drag。

### 11.3 采音型反例：逻辑断裂与不可预测性

**特征一：同一段内采音对象切换无规律（N4）。**

"神秘踩音"和"同一段一会踩旋律一会踩鼓点一会踩人声"指向同一问题：**采音的主导层在段内发生了玩家无法预测的切换**。

采音切换本身不是问题，第八卷"按结构分组采音"允许在段落边界更换采音重点。**问题在于切换发生在段内，且没有听觉或视觉上的信号。**例如前 4 拍采底鼓，后 4 拍突然采人声装饰音，而底鼓在这 4 拍中仍存在且强度不变。玩家会根据前 4 拍建立"这段采鼓"的预期，后 4 拍的人声采音会让他们漏掉底鼓音符。

**检测标准**：对于同一段落的连续 16 拍，**若采音对象（底鼓/军鼓/主旋律/人声/装饰音）发生 2 次以上切换，且每次切换持续不足 8 拍，则该段采音逻辑不成立。**合理的采音切换至少应持续 8–16 拍，让玩家有足够时间建立和调整预期。

**特征二：变速踩音在低定数谱面中出现。**

"神秘踩音"的另一个维度是**采音时间点与 BPM 网格的偏离在低难度谱面中过大**。低定数谱面（Lv.14 以下）玩家预期音符落在可预测的拍点上。若在 14 级中使用大量 ±10ms 以上的手动偏移采音（第八卷作为"专业做法"提到的），玩家会感到"节奏不对但说不出哪里不对"。

**AI 的修改策略**：Lv.14 以下的谱面，采音偏移应控制在 **±5ms 以内**，快慢刀使用频率**低于全谱 10%**。Lv.16 以上可放宽到 ±10ms 和 20%。

**特征三：对齐视觉与听觉的错位（N5）。**

"每一组长条都和下一组的第一个 note 对齐，很干扰读谱"。谱面中出现视觉上明显的对齐关系（长条尾部与下一音符起始位置在 X 轴重合），但听觉上这两个事件没有节奏对应。玩家会本能将视觉对齐解读为节奏对齐，从而在错误时间点击。

**检测标准**：**若两个音符 X 距离小于 50 单位，且时间间隔不是 4 分、8 分或 16 分音符的整数倍，触发视觉对齐干扰警告。**解决方案：错开 X 坐标至少 100 单位，或将其中一个音符的时间调整到最近拍点。

### 11.4 机制型反例：可读性预算的透支

**特征一：判定线运动与高密度同时出现（N6）。**

第九章原则一的直接违反。**检测标准**：在任意 4 拍窗口内，**若判定线 moveX 或 moveY 事件的瞬时速度（数值变化量/时间）超过该谱面平均速度的 3 倍，且该窗口 NPS 超过该谱面平均 NPS 的 1.2 倍，触发可读性透支警告。**

**特征二：多线同时承载需要操作的音符（N7）。**

第九章原则二的违反。**若同一时刻有两条或以上判定线上存在真实音符（非 isFake），且这些音符的判定时间间隔小于 8 分音符，玩家需在两条线间切换注意力。**合理的多线设计是：一条线承载操作，另一条承载视觉（假音符或纯表演线），**操作线与视觉线的 alpha 对比至少 2:1（操作线更不透明）**。

**特征三：快慢刀出现在采音不清晰段落（N8）。**

第九章 10.4 的违反。**若快慢刀所在段落的第一层采音密度低于每拍 1 个音符，玩家无法通过听觉判断时机，快慢刀就变成"只能背谱"的恶意设计。检测标准：快慢刀段落的第一层采音覆盖率（有第一层音符的拍数/总拍数）应不低于 75%。**

### 11.5 定数型反例：标级与内容的系统性偏差

**特征一：虚低——机制复杂度超出标级（N9）。**

"混乱（14.8）虚低，交互容易爆 g，判定线导致读谱难度较大"是典型。14 级标级下玩家预期"单线或简单多线，机制可预测"。若在 14 级中使用持续轴交互或倒打，即使 NPS 不高，读谱难度已进入 16 级区间。

**检测标准**：统计谱面中"判定线旋转超过 45° 且同时存在需要操作的音符"的持续时间。**若超过全谱 10% 且标级在 15 以下，触发虚低警告。**倒打（旋转超过 135°）持续时间超过 5% 且标级在 15 以下，同样触发。

**特征二：虚高——机制过于简单但 NPS 偏高（N10）。**

"逆诈称"的反例讨论较少但存在。若一张 16 级谱面的全部难度来自"纵连速度"，没有读谱、定位、手序的复合压力，高底力玩家会认为"简单"，底力不足的玩家会认为"难但无聊"。**谱面的定数应由最短板决定，而非单一维度的峰值。**

**AI 的修改策略**：**若生成的谱面中 70% 以上的音符集中在纵连或交互（单一手序模式），而轴交互、大位移、多线等机制的出现时间不足 20%，应降低标级 0.5–1 级，或在描述中标注"纯底力向"。**

**特征三：纵连起手无引导（N11）。**

"所有纵连的起手全部为普通 note，也就是不分左右手，相当没有引导，如果完全按照其起手会乱手序"。纵连本身是中性配置，但**若纵连第一颗音符没有通过位置或类型暗示"该用哪只手起手"**，玩家会在纵连开始的第一瞬间犹豫，而纵连节奏不允许犹豫。**解决方案：在纵连第一颗音符上使用与后续不同的位置（偏左或偏右），或用 Flick 标记起手侧。**

生成谱面后逐条执行。**任何一条触发，标记为"需要修改"而非"可交付"。**

| 编号 | 检测项 | 阈值 | 修改方向 |

### 11.7 本章核心结论：反例的价值在于可检测

正面范本告诉 AI"应该做什么"，反例告诉 AI"什么不能交付"。**反例的价值不在于描述性批评（"这谱很粪"），而在于可量化的检测规则。**12 条检测项每一条都对应一个具体的谱面数据特征（NPS 窗口、X 坐标分布、时间间隔、采音覆盖率、事件速度），AI 可在生成后直接计算这些指标，而非依赖主观判断。

**需诚实说明的局限**：这些检测项只能捕获"结构性失败"，无法捕获"平庸"。一张通过全部 12 项检测的谱面，可能仍然没有记忆点、没有情绪起伏、没有演出设计。**反例集锦的作用是排除下限，而非保证上限。**上限仍依赖第十一章的范本学习和对具体曲目的审美判断。

**工程建议**：AI 调用 `chart_script` 或 `chart_generate` 生成谱面后，应额外执行一次**密度统计和 X 分布统计**（可通过 `chart_query` 或脚本内简单计算完成），将结果与本章阈值对照，而非直接提交给用户。检测报告应作为审批前的附加上下文呈现，让用户知道这份谱面通过了哪些检查、哪些项需要人工判断。

### 可量化的反例指标补充：X 集中度 / 等间距率 / 屏外音符率

除 N1–N12 外，以下三个比率能定量抓住"看起来单调"和"根本打不了"的问题，建议交付前自查：

| 指标 | 定义 | 阈值 | 说明 |
|---|---|---|---|
| X 集中度 | \|positionX\| ≤ 300 的音符占比 | > 55% 判为中央偏载 | 社区成熟谱参考值约 41% |
| 等间距率 | 相邻音距恰为十六分的比例 | 任意 16 拍窗口 > 50% 判为机械流水 | 流水线的直接量化 |
| 屏外音符率 | 屏幕 X 超出 ±675，或落在 alpha < 0 区间的音符占比 | 必须为 0 | 一旦 > 0 就是"打不了"的谱面 |

**X 分布的标尺**：按 150 宽分箱统计全谱 positionX，社区成熟谱的参考分布为 `[423,525,444,80,699,78,440,537,410]`——中间箱（-75~75）只有 80，两端却接近 700，呈现"两端密、中间疏"的双手分工。自造谱若呈"中间密两端稀"，说明音符全挤在中心、两侧屏幕闲置，是单调的主要来源。

**屏外音符自检**：对每条线按时刻采样 moveX 与旋转角 θ，计算 `屏幕X = moveX + positionX × cos θ`，落在 ±675 之外的音符即为屏外。**倒打段必须参与这项计算**（cos180° = -1），用正打口径验算会整段漏掉。

**同位纵连自检**：同一判定线上连续 ≥3 个音符的 positionX 差值均小于 60，即为假纵连（玩家按一根手指全接），与真纵连的区别在于真纵连有明确的设计意图且 X 有变化。

## 十二、AI 制谱决策清单

在设计或修改谱面时逐条检查：

**采音与物量**

1. **主导层**：此刻最该被表现的声音是哪个？同刻想表现三个声音但轨道分配会别扭或密度失控时，只保留最重要的那个。
2. **采音分层**：第一层（鼓+旋律重音）是否已超 NPS？超了就砍第二层，不要靠加注解决。
3. **舍音层级**：按层内舍（只留重拍）→ 层间舍（弃第二层）→ 类型替换（Tap→Drag）→ 视觉暗示（表演线假音符）的顺序执行，不要跳级。
4. **物量与欺诈**：Drag 占比是否过高导致"物量欺诈"体感？Drag 是否只用在密集段作视觉填充、关键重拍仍用 Tap？
5. **采音一致性**：副线的功能分工是否稳定？段与段之间的采音重点切换是否给出明显信号？

**密度与手感**

6. **密度曲线**：是否呈波浪形？有无长时间维持峰值？每个 16 拍统计一次 NPS。
7. **休息段**：爆发后是否有真正低密度 + 简单机制的 Break？
8. **打击感**：音符类型与音乐情绪是否匹配（重拍用 Tap/Flick、流动用 Drag、持续音用 Hold）？
9. **伪音符位置**：假音符是否只出现在玩家"预期不需要操作"的位置？主线判定区正中央不应放假音符。

**人体工学与可读性**

10. **手序冲突**：主线高密度 Tap 是否集中在中央？副线 Hold/Flick 是否在边缘？同一时刻是否有一手连打 + 另一手长按？
11. **可读性预算**：判定线运动与音符密度是否同时拉满？同一时刻视觉信息源是否超过两个？需要适应新轴向前判定线是否已提前到位并停顿至少一拍？
12. **判定线运动耦合**：剧烈运动段的流速是否已降低？谱面是否有稳定视觉锚点？
13. **事件连续性**：所有事件首尾值是否严格相等？连接处缓动类型是否统一？
14. **机制可解性**：轴交互的判定线是否在音符生成前已到位并停顿？倒打段是否有节奏一致性？

**定数与伦理**

15. **定数自评**：读谱难度与底力难度是否分别评估？描述中是否提示了偏科方向？
16. **伦理检查**：初见杀是否可预测？快慢刀是否放在采音清晰处？体力墙是否诚实预告？
17. **可控域判定**：玩家抱怨的是你的可控域（采音/耦合/密度）还是他的不可控域（资源包/设备/着色器）？后者不必改谱。

**反例自检（第十一章 N1–N12）**

交付前必须计算并对照全部 12 项检测，触发任一条即为"需要修改"而非"可交付"：

| 编号 | 检测项 | 阈值 |
| --- | --- | --- |
| N1 | 连续高密度窗口 | 3 个 16 拍窗口 NPS > 峰值 80% 且无 <50% 窗口 |
| N2 | 中央区域过载 | 连续 8 拍 X∈[-200,200] 占比 >90% 且 NPS>10 |
| N3 | 大位移无缓冲 | 相邻手序音符 X 距离>400 且间隔<16分 |
| N4 | 采音切换过频 | 16 拍内采音对象切换≥2 次且每次<8 拍 |
| N5 | 视觉对齐干扰 | 两音符 X 距离<50 且时间间隔非 4/8/16 分整数倍 |
| N6 | 判定线运动+高密度 | 4 拍内线速度>均值 3 倍且 NPS>均值 1.2 倍 |
| N7 | 多线操作冲突 | 两条线同时有真实音符且判定间隔<8 分 |
| N8 | 快慢刀采音不清 | 快慢刀段第一层采音覆盖率<75% |
| N9 | 低定数高风险机制 | 标级≤15 且轴交互>10% 或倒打>5% |
| N10 | 单一手序过载 | 纵连/交互占比>70% 且复合机制<20% |
| N11 | 纵连起手无引导 | 纵连起始音符与后续音符同类型同位置 |
| N12 | 反手无预告 | 反手配置前 8 拍内无指向性引导音符 |

**检测报告要求**：生成谱面后执行一次密度统计与 X 分布统计（`chart_query` 或 `chart_script` 均可），将结果与上表阈值逐条对照，把检测报告作为提交前的附加上下文呈现给用户，说明哪些项通过、哪些项需人工判断。**这些检测只排除结构性失败，不能保证上限**——记忆点、情绪起伏与演出设计仍需第十一章的范本学习与审美判断。

| `isFake` | 1 为假音符（不计分、不可打） |
| `speed` | 下落速度倍率 |
| `size` | 宽度倍率 |
| `yOffset` | 纵向偏移 |
| `visibleTime` | 提前多久可见 |
| `alpha` | 音符透明度 0-255 |

### 拍数表示

`[整数, 分子, 正分母]`，值 = 整数 + 分子/分母。`fromNumber` 用 19200 分母做最小整数比约分。命令也接受十进制或 `3:1/2` 形式。

### 透明度事件语义

| 值 | 效果 |
| --- | --- |
| 0 | 仅隐藏判定线，音符仍显示 |
| 负数 | 同时隐藏判定线及其音符（噪域的实现基础） |
| 1-255 | 正常透明度 |
